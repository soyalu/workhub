# M1.7 地标精定位：视觉坐标与文字安全区

## 来源与问题
以用户提供的整幅地图截图（1686×895）与已入库的七张 510×325 透明 WebP 校准。过去所有地标使用相同的文字左偏移 90px，这实际上侵入了位于组合图左侧的盾牌/卷轴（正文应从原画暗蓝横幅的净空部分开始）；过去的地图坐标分散在旧 CSS 中。

## 实现方案
- \`landmarkLayout.ts\` 维护七组独立的地图中心坐标（%）、组合图渲染宽高/偏移和文字安全区（px）。
- 默认仍使用 \`combined/{theme}.webp\`：正式金属徽章与横幅不重新拼接。
- 文字由 React 动态渲染、图片作为纯装饰；导航继续使用可访问的 Link。
- 正式图加载成功后才启用精定位 CSS；图片不可用时保持原有回退布局。
- Motion 激活时图与文字同步向上 2px，避免过去横幅单独缩放、文字向右漂移而造成的错位；PixiJS 单 Canvas 不改动。
- 手机上改用两列网格与相对定位，压缩副标题以保证主标题可读。

## 验收
- 不同地标独立坐标可追踪。
- 文字与金属徽章不重叠；副标题在宽屏正常显示，手机端保留在 aria-label。
- 所有 7 个 DOM Link 能正确跳转，粒子点击穿透。
- 两种尺寸截图与原稿人工逐项比对。

## 七地标文字垂直居中修正
实际 510×325 WebP 的金色横幅上下边界不完全一致。基于 x=350 的金边纵向测量，七组横幅中心 Y 分别为 quest 184.5、project 180.5、message 184.5、capture 194、calendar 192、side 193.5、growth 192.5。
新增 bannerCenterSourceY，文字上边距通过 imageTop + imageHeight × (bannerCenterSourceY / 325) − textHeight / 2 自动计算；桌面、平板、390px 手机分别采用实际绘制尺寸。
不改变地图中心坐标、徽章宽高、文字左边距及 PixiJS 效果。Playwright 同时检查 1440px 和 390px 的横幅纵向对齐误差。
